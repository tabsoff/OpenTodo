# Согласованный формат разработки OpenTodo

Эти договорённости относятся к разработке пользовательской версии OpenTodo в этом репозитории.

- Основной режим доработок — локальный предпросмотр на компьютере пользователя, доступный только через localhost, с отдельной тестовой базой и вымышленными задачами.
- Для интерфейса использовать автоматическое обновление страницы при изменениях кода. При изменениях серверной части при необходимости перезапускать локальный сервер.
- Во время подбора результата показывать изменения локально. Не запускать полный GitHub CI, не открывать PR и не выкладывать каждую промежуточную правку на VPS. Локальные проверки, нужные для конкретного изменения, выполнять по мере необходимости.
- После одобрения результата пользователем оформить PR, выполнить обязательные проверки и использовать существующий процесс: тестовый сайт → проверка результата → отдельное решение о рабочем выпуске с подтверждением владельца.
- Согласие с локальным предпросмотром не является разрешением на рабочий выпуск. Рабочие данные и учётные записи не использовать для локальных экспериментов.
- Сохранять требования репозитория к спецификациям и проверкам перед выпуском. Локальный предпросмотр ускоряет итерации, а не заменяет эти проверки.

Формат согласован 23 октября 2026 года. Локальное окружение Windows подготовлено и проверено на первой доработке календаря.

## Локальный предпросмотр на Windows

1. Откройте `scripts/tabsoff/start-preview.cmd` двойным кликом.
2. Откройте http://localhost:5173. Данные вымышленного аккаунта находятся в соседнем с репозиторием каталоге `../local-preview/credentials.json`.
3. Меняйте интерфейс в `web/src`: Vite подхватывает изменения автоматически. После изменений Go или серверных ресурсов остановите и снова запустите предпросмотр.
4. Для остановки откройте `scripts/tabsoff/stop-preview.cmd`. Тестовая база сохраняется.

Требования: Node.js, зависимости из `web/package-lock.json`, Go из `toolchain` в `go.mod`. На этом компьютере Go установлен отдельно в `../runtimes/go1.27.3/go`; системные настройки не менялись. Если portable Go отсутствует, запуск использует Go из PATH. Первая установка зависимостей и сборка могут требовать интернет. Последующие изменения интерфейса не требуют пересборки сервера или загрузки на VPS.

API слушает только `127.0.0.1:8080`, интерфейс — `localhost:5173`. Отдельная база, журналы и запись процессов лежат в `../local-preview`; Go-кэши — в `../go-cache` и `../go-build-cache`. Эти каталоги находятся вне репозитория. Не добавляйте учётные данные, базу или журналы в Git.

Если порт 8080 или 5173 занят, запуск останавливается с сообщением и не завершает существующие процессы. Повторный запуск уже работающего предпросмотра ничего не дублирует. Остановка проверяет путь и время запуска записанных процессов, чтобы не завершить другой процесс при повторном использовании PID.

## Первая доработка: создание на сетке

В Settings → General → Calendar → Task colors можно выбрать By list (исходный вариант) или By priority. Выбор общий для всех режимов календаря и сохраняется на устройстве. Приоритеты: P1 красный, P2 оранжевый, P3 синий, P4 серый; внешние события сохраняют цвет своего календаря. В локальном предпросмотре для демонстрации включён By priority.

Высоту верхней области можно менять горизонтальным разделителем мышью или касанием. Списки дней прокручиваются независимо, заголовки остаются на месте. Высота сохраняется на устройстве и общая для «Дня» и «Недели»: 144 px по умолчанию, диапазон 80–480 px с ограничением по высоте окна. На разделителе доступны стрелки вверх/вниз (16 px), Home/End; Escape отменяет незавершённое растягивание. Линия текущего времени скрывается под верхней областью.

Протягивание по свободному месту выбирает длительность новой задачи. Мышью нажмите и протяните вниз или вверх; пальцем сначала удерживайте 350 мс. Подсветка показывает интервал, после отпускания он переносится в форму. Шаг — 15 минут; выбранный день фиксируется, окончание ограничено 24:00. Быстрый свайп пальцем прокручивает календарь. Escape, отмена касания и потеря фокуса окна отменяют выделение. Обычный клик открывает форму с выбранным временем и длительностью 15 минут; кнопка «+» — без времени, с оценкой 15 минут.

В режиме «День» или настольной «Неделе» кликните свободное место: откроется форма названия, описания, времени и длительности. Флажок рядом с названием выбирает приоритет P1–P4, по умолчанию P4. Дата определяется столбцом, время округляется вниз до 15 минут; длительность первоначально 15 минут. Кнопка «+» в заголовке дня доступна с клавиатуры и открывает форму с датой, но без времени. Без явного указания времени задача остаётся в верхней нераспределённой области. Enter в названии сохраняет во «Входящие», в описании добавляет строку. Escape сначала закрывает открытое меню приоритета, затем — форму; «Отмена» закрывает форму без создания. Месяц и недельный список на телефоне работают по-прежнему.

Проверены создание в обоих режимах, координаты после прокрутки, Enter, перенос/изменение размера/открытие существующей задачи. При остановленном тестовом API задача сохраняется локально; после его запуска синхронизируется с тем же идентификатором без дублей. Автоматические тематические тесты дополнительно покрывают границы дня, изменение полей, отмену, ошибки, повторную отправку и отменённые жесты.

Пользовательская инструкция: [USER-GUIDE.md](USER-GUIDE.md). Техническая инструкция: [README.md](README.md).

Calendar overlap markers can be hidden in General > Calendar > Overlap markers. This device-only preference is left off in the synthetic local preview; it does not change overlap layout or stack controls.
